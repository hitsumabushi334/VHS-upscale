## 5. ブロック要因 B: FFmpeg 8.1.1 で short fixture の color metadata が欠ける

### 事実（coordinator が Windows 上で直接確認）

- 既存 fixture 生成コマンド（tests/test_short_inference_contract.py の vhs_fixture）は
  -color_range tv -colorspace smpte170m -color_primaries smpte170m -color_trc smpte170m -vf scale=...,setsar=10/11 を使用。
- FFmpeg 8.1.1（現環境）で同じコマンドを実行し ffprobe した結果:
  **color_range=tv, color_space=smpte170m, color_primaries=空, color_transfer=空, SAR=10:11, progressive**。
  → primaries/transfer が書かれない。scale filter の out_color_primaries は FFmpeg 8.1.1 で Option not found。
- **baseline 時点（Task 0）でも FFmpeg は既に 8.1.1**（baseline.json の windows.ffmpeg で確認）。
  ただし Task 0 の integration 25 PASS は **WSL venv 経由**（WSL 側 FFmpeg を使用）なので、
  Windows 直実行での short suite PASS は本セッションでは一度も観測されていない。
  → **既存の潜在問題（Task 5 リファクタ起因ではない）**。
- 結果: Windows 直実行では fixture が「metadata 欠損」になり fail-closed 契約が正しく reject するため
  reject 系テストは通るが accept 系（fixture_preflight_passes 等）が失敗する。
  「fail-closed 挙動は保たれている」が「accept 系は失敗」。

### 対応方針（次セッションで判断）

- WSL harness で regression を完遂できるなら **fixture 修正は不要**。
- Windows 直実行も green にしたい場合: vhs_fixture の color metadata 書き込みを FFmpeg 8.1.1 で動作する方式に更新
  （候補: -vf に setparams=color_range=tv:colorspace=smpte170m:color_primaries=smpte170m:color_trc=smpte170m を追加）。
  テストfixture生成の修正であり契約挙動変更ではない。実施時は PLAN DEVIATION に記録。
  修正するなら short/long 両 fixture を同じ方式で揃える。
