## 3. 短尺ランナー(run_short_inference.py)

5〜10 秒素材を TAPE で復元し、FFV1 video + 元音声 remux の Matroska と
`report.json` を作る。検証済みコマンド(WSL 内で実行):

```bash
wsl.exe -d Ubuntu-22.04 -- /bin/bash -lc '
  cd /mnt/e/vhs-upscale
  P=/mnt/e/vhs-upscale/worktrees/tape-rocm-rx7900xt-luna/.venv-rocm/bin/python
  $P scripts/run_short_inference.py \
    --input input/VHS_10s_ready.mkv \
    --checkpoint work/assets/checkpoint.pth \
    --output work/tmp/<run-name> \
    [--patch-size 256]
'
```

- 相対パスで問題ない(2026-09-22 修正で、CWD 基準で解決してから
  worktree CWD 境界を跨ぐ)。
- `--python` で WSL venv python を渡すのが WSL 実行の正しい形
  (WSL 内でこの venv python を直接用いる場合は不要)。
- 成果物: `<output>/report.json`、`<output>/<stem>/restored_frames/*.png`、
  FFV1+音声 MKV。
- `report.json` の `status`:
  - `ok`: 推論 + media contract すべて通過
  - `contract_failed`: 推論は成功したがお約束(フレーム数・音声 packet 数・
    duration・color)が破綻 — `contract` フィールドで項目を確認
  - `inference_failed`: TAPE 実行自体の失敗 — `problems` に traceback

## 5. 既知の制約とトラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| `torch.OutOfMemoryError: HIP out of memory`(短尺ランナー) | patch 512 の Swin-3D attention は実機 1280x720 で 20GB 級の VRAM を要求。WSL2 は Windows デスクトップと VRAM を共有 | (a) `--patch-size 256` に落とす (b) `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` を設定してフラグメンテーションを緩和 (c) Windows 側 GPU 負荷(ゲーム・描画)を下げる。patch 512 のデフォルトではデスクトップ無負荷でもギリギリ |
| Windows 側 VapourSynth テストが RED(TC-01) | QTGMC native plugin 欠如 | `install_vapoursynth.ps1 -Apply`(ユーザー承認必須) |
| Windows での integration 群で `color_primaries` 欠如による PreflightError | vhs_fixture の ffprobe 出力が環境依存(WSL では green) | 環境要因として記録済み。canonical 判定は WSL ハーネスで行う |
| `Failed to read frame from video` | (2026-09-22 修正済み)相対パスが worktree CWD 基準で解決されていた問題 | 現行コードでは解決済み。再発すれば report の traceback を確認 |
| pytest の WinError 5 | drvfs の file-locking | `--basetemp E:\vhs-upscale\work\tmp\<fresh>` を必ず fresh にする |
