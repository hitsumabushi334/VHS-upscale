# TAPE ROCm RX 7900 XT Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** WSL2 Ubuntu 22.04上のRX 7900 XTで、TAPE公式checkpointのstrict load、有限値forward、PNG中間frameを使った5～10秒VHS推論を成立させる。

**Architecture:** TAPE upstreamを隔離worktreeで最小修正し、純粋関数の回帰テスト、ROCm環境preflight、asset provenance、checkpoint smoke testを独立させる。ROCm/PyTorch、TAPE model、CLIP/Swin-T、動画I/Oの境界を順番に検証し、失敗原因を混在させない。

**Tech Stack:** Windows 11、WSL2 Ubuntu 22.04、Python 3.10、ROCm 7.2 legacyまたは検出済みROCDXG、PyTorch 2.9.1、torchvision 0.24.0、OpenAI CLIP `a1d0717`、pytest、OpenCV、FFmpeg/ffprobe、PNG、FFV1 Matroska。

**Spec:** `docs/superpowers/specs/2026-09-14-rx7900xt-tape-rocm-design.md`

**Test Cases:** `@./test_cases.md`

## Global Constraints

- 実装・環境構築・実機検証は`gpt-5.6-luna` / `xhigh`のsubagentへ委任し、main agentは計画、checkpoint判定、レビュー統合を担当する。
- 対象GPUはこのPCのAMD Radeon RX 7900 XTのみとする。
- Windowsドライバーは自動変更しない。変更が必要なら原因証拠を提示して別途承認を得る。
- TAPEのCUDA用`install_requirements.sh`を実行しない。
- `torch.cuda` APIとdevice string `cuda`はROCmでも維持する。
- ROCm 7.2 legacy経路とROCDXG経路を混在させない。未導入環境でlibrary不存在をruntime選択根拠にせず、setup時に`--runtime legacy|rocdxg`を必須指定する。
- TAPE checkpointは`strict=True`でロードし、`strict=False`で成功扱いしない。
- 本処理のframe形式はPNGとし、JPEG intermediateを生成しない。
- PNGは可逆圧縮だが、現行TAPEのOpenCV経路は8-bit RGB/BGRである。`lossless codec`と`lossless signal path`を同一視せず、量子化位置とdtype/value rangeを記録する。
- 元動画を上書き、移動、削除しない。
- 取得assetは公式配布元、byte size、SHA-256を記録する。
- 各実機検証はJSONログとテキストログを`E:\vhs-upscale\work\logs\tape-rocm\`へ残す。
- RealBasicVSR、Modal、QTGMC、長時間chunk処理は本計画の実装対象外とし、本計画の測定結果を次計画へ渡す。ただし短尺TAPE入力は将来のQTGMC出力契約と同じprogressive/CFR/media manifestを要求し、raw interlaced captureを暗黙に入力しない。

```python
def resolve_reference_names(img_names, clean_indexes, ranked_local_indexes, count):
    if count < 1:
        raise ValueError("count must be positive")
    if len(img_names) == 0:
        raise ValueError("img_names must not be empty")
    if len(clean_indexes) == 0:
        selected = [str(img_names[0])]
    else:
        selected = [str(img_names[clean_indexes[i]]) for i in ranked_local_indexes[:count]]
        if not selected:
            selected = [str(img_names[clean_indexes[0]])]
    return selected + [selected[0]] * (count - len(selected))

def resized_dimensions(width, height, patch_size):
    if width <= patch_size and height <= patch_size:
        return width, height
    if height > width:
        return int(width * patch_size / height), patch_size
    return patch_size, int(height * patch_size / width)
```

- [ ] **Step 3: short inference runnerを実装する**

runnerは実行前にffprobe JSONから`pix_fmt`、`color_range`、`color_space`、`color_primaries`、`color_transfer`、`sample_aspect_ratio`、`display_aspect_ratio`、`field_order`、`avg_frame_rate`、`r_frame_rate`、`time_base`、audio stream情報をmedia manifestへ保存する。入力がprogressive/CFRでなく、必須の色・SAR情報が欠損している場合は推測せず停止する。入力SHA-256を実行前後で比較し、専用output directoryへTAPEを`--frame-format png --no-intermediate-products`なしで実行する。復元PNG sequenceをmanifestの値を明示したFFmpeg引数でFFV1へencodeし、入力audioをstream copyでremuxする。成功後にのみ一時frame削除を許可する。

Encode contract:

```bash
ffmpeg -framerate 30000/1001 -start_number 0 -i restored/%08d.png -vf "scale=out_color_matrix=smpte170m:out_range=tv,setsar=10/11" -fps_mode cfr -c:v ffv1 -level 3 -g 1 -slicecrc 1 -pix_fmt yuv422p10le -colorspace smpte170m -color_primaries smpte170m -color_trc smpte170m -color_range tv -field_order progressive video_only.mkv
ffmpeg -i video_only.mkv -i input/VHS_10s.mkv -map 0:v:0 -map 1:a? -c copy VHS_10s_tape.mkv
```

上記は29.97p、BT.601系NTSC metadata、SAR 10:11、`%08d.png`連番の具体例であり、これらを全入力へhard-codeしない。runnerはmanifestの値をallowlist mappingでFFmpeg optionへ変換する。`avg_frame_rate`は有理数文字列のまま取得し、`0/0`・欠損・非正値を拒否する。frame filename patternはTAPE出力の実ファイル名から検証し、shell文字列連結ではなくargument listでsubprocessへ渡す。Matroska muxerが選ぶvideo `time_base`は完全一致を要求せず、frame count・CFR rate・duration/timestamp整合で検証する。

media contractの判定は次の2群に分ける。

- 保持: `color_range`、`color_space`、`color_primaries`、`color_transfer`、SAR/DAR、CFR frame rate、audio stream数・codec・duration。
- 意図的変更: video codecはFFV1、`pix_fmt`は`yuv422p10le`、`field_order`はprogressive、container/time baseはMatroska mux結果。TAPE内部はinput PNG、OpenCV decode、model float `[0,1]`、output PNGの各dtype/bit depthをreportする。
